# 📊 Nginx IPv6 Bug Fix Report

**Date**: May 01, 2026  
**Issue**: Client 3 stuck when trying to watch movies - slot not re-distributed to Server A even when Server A is empty  
**Root Cause**: Nginx IPv6 resolution bug  
**Status**: ✅ **FIXED**

---

## 🔴 **Vấn Đề Chi Tiết**

### Triệu Chứng
```
Client 1, 2: Xem phim OK trên Server B (2/2 slots full)
Client 3: Cố kết nối, nhận lỗi "could not connect to media"
Server A: Trống (0/2 slots), nhưng Client 3 không thể vào

Logs từ Desktop:
  WARNING: onError, errCode=0, msg=could not connect to media
  (http://localhost:8080/api/hls/1/360p/playlist.m3u8?userEmail=...)
  [Retry lần 1, 2, 3, ...] - vẫn fail
  
Logs từ Nginx:
  [error] connect() to [fdc4:f303:9324::254]:8082 failed (101: Network unreachable)
  [LB] request="/api/hls/1/360p/segment_002.ts" server="8082 -> 8081" retry="co" upstream_status="502, 200"
```

### Nguyên Nhân Gốc

**Lớp 1: Sticky Session (ip_hash)**
- Nginx config: `ip_hash;` → Client 3's IP → định tuyến tới Server B
- ✅ **Đúng**: Sticky session hoạt động

**Lớp 2: DNS Resolution Bug** ❌
```
Nginx config:
  upstream hls_backend {
      server host.docker.internal:8081 max_fails=0;
      server host.docker.internal:8082 max_fails=0;
  }

DNS Resolution từ Docker:
  $ nslookup host.docker.internal
  Name:   host.docker.internal
  Address: fdc4:f303:9324::254    <- IPv6 link-local address ❌
  Address: 192.168.65.254          <- IPv4 address ✅

Nginx behavior:
  - Resolve hostname at startup
  - Prefer IPv6 (RFC priority)
  - Try [fdc4:f303:9324::254]:8082 → FAIL (servers not listen on IPv6)
  - [error] connect() to [fdc4:f303:9324::254]:8082 failed (101: Network unreachable)
  - Retry [fdc4:f303:9324::254]:8081 → FAIL too
  - Finally retry 192.168.65.254:8081 → ✅ 200 OK
  - Client see 502 from first attempt ❌
```

**Lớp 3: Client Behavior**
```
Client 3 (assigned to Server B):
  Request 1: Nginx → [fdc4:f303:9324::254]:8082 → FAIL (502)
           → Nginx retry → [fdc4:f303:9324::254]:8081 → FAIL (502)
           → Nginx retry → 192.168.65.254:8081 → ✅ 200
           → But client gets 502 from first response ❌
  
  Client 3 thinks: "Server is down" → Retry with backoff
  → Stuck in retry loop
  → Can't access any server until Client 1 or 2 stop
```

## ✅ **Giải Pháp**

### Fix 1: Remove Hostname, Use Explicit IPv4 Address

**Before:**
```nginx
upstream hls_backend {
    ip_hash;
    server host.docker.internal:8081 max_fails=0;
    server host.docker.internal:8082 max_fails=0;
}
```

**After:**
```nginx
upstream hls_backend {
    ip_hash;
    server 192.168.65.254:8081 max_fails=0;     # ← Explicit IPv4
    server 192.168.65.254:8082 max_fails=0;     # ← Explicit IPv4
}
```

**Why:**
- Direct IP → No DNS resolution → No IPv6 vs IPv4 confusion
- Nginx connects directly to 192.168.65.254:8082 (Server B)
- Fast connection, no retry needed

### Fix 2: Add IPv4-Only DNS Resolver

**Added to nginx.conf:**
```nginx
http {
    # DNS resolver - IPv4 only, không dùng IPv6
    resolver 127.0.0.11 ipv6=off;
    resolver_timeout 5s;
    ...
}
```

**Why:**
- Backup resolver config
- Force DNS to return IPv4 only
- Ensures future resolution (if we use dynamic hostnames) prefer IPv4

## 🔍 **Technical Details**

### IPv6 Link-Local Address Explained
```
[fdc4:f303:9324::254] = IPv6 link-local address
  - Generated by Docker for container networking
  - Not routable to host machine
  - Only valid within Docker bridge network
  
192.168.65.254 = IPv4 address (Docker Desktop host gateway)
  - Reachable from Nginx container
  - Maps to host machine
  - Servers listen on this IP
```

### Why Nginx Tried IPv6 First
1. Modern systems prefer IPv6 (RFC 6724)
2. DNS resolver returned both IPv4 and IPv6
3. Nginx tried IPv6 → failed
4. Nginx retry IPv4 → succeeded
5. But client doesn't wait for retry

### Why `host.docker.internal.ipv4` Didn't Work
```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
  - "host.docker.internal.ipv4:host-gateway"
```
Both map to `host-gateway`, which Docker resolved to both IPv4 and IPv6.
Solution: Skip hostname entirely, use explicit IP.

## 📞 **Troubleshooting**

### Still seeing IPv6 errors after restart?
```bash
# Force clean restart
docker stop hls-lb && docker rm hls-lb
docker-compose up -d

# Or pull latest nginx image
docker pull nginx:1.27-alpine
docker restart hls-lb
```

### Nginx can't reach servers?
```bash
# From inside Docker, test connection
docker exec hls-lb curl -v http://192.168.65.254:8081/api/movies

# Check hosts file inside Docker
docker exec hls-lb cat /etc/hosts | grep host.docker.internal
```

### Still getting 502 on some requests?
- Check if servers are actually running on ports 8081, 8082
- Check server logs for errors
- Verify firewall rules allow 192.168.65.254:8081-8082
